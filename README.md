# ADAM — журнал посещаемости и баллов

Next.js 14 + Prisma + PostgreSQL. Преподаватель отмечает посещаемость и ставит баллы за занятия.
Ведомости и итоговые оценки считает GAUDI, в этом проекте их нет.

## Запуск

```bash
npm install                      # заодно выполнит prisma generate
cp .env.example .env             # заполни DATABASE_URL, AUTH_SECRET, JWT_SECRET, TEST_PASSWORD
npx prisma migrate deploy        # создаёт таблицы (одна чистая миграция под PostgreSQL)
npx prisma db seed               # тестовые данные (стирает старые!)
npm run dev                      # http://localhost:3000
```

Проверка перед выкладкой: `npx tsc --noEmit` и `npm run build`.

## Демо-доступы (после `prisma db seed`)

Вход по логину (id пользователя) и паролю из `TEST_PASSWORD`.

| Роль | Логин |
|---|---|
| Преподаватель | `TKUZOL` (дисциплины с картами, группы ИСТ-5-24/25), `TIVANOV`, `TBELMAX` и др. |
| Руководитель направления | `HEADIST1` (ИСТ), `HEADECO1` (экономика) |
| Учебная часть | `UCHTEST1` |
| Куратор | `CURTEST1` |
| Студент | `STUDTST1` |

## Деплой на Vercel

1. Создайте базу PostgreSQL (например, Neon) и скопируйте **прямую** строку подключения.
2. Залейте проект на GitHub (в репозиторий не попадают `.env`, `node_modules`, `.next`).
3. В Vercel: Add New → Project → выберите репозиторий. Framework: Next.js.
4. Environment Variables: `DATABASE_URL`, `AUTH_SECRET` (длинная случайная строка), `TEST_PASSWORD`.
   Без `AUTH_SECRET` и `TEST_PASSWORD` приложение в продакшене не пустит пользователей.
5. Сборка (`vercel-build`) выполняет `prisma generate`, подготовку базы (`scripts/db-bootstrap.mjs`),
   `prisma migrate deploy` и `next build`.
6. Первый деплой на новой или старой базе. Добавьте две переменные окружения (можно оставить навсегда, они безопасны):
   - `ALLOW_DB_RESET=true` — если в базе остались таблицы от старой версии без истории миграций, схема `public` будет очищена
     (данные удалятся!). После первой успешной миграции этот флаг уже ничего не стирает.
   - `SEED_ON_BUILD=true` — если таблица `users` пуста, база наполнится тестовыми данными (логины из таблицы выше).
   Без `ALLOW_DB_RESET` сборка на непустой «старой» базе остановится с понятным сообщением.
   - `DEMO_SCHEDULE_VERSION=<любая строка>` — один раз для этой версии загружает демо-расписание (`prisma/seed-schedule.ts`):
     занятия нон-стопом каждые 30 минут, по 4 одновременно, 13 преподавателей, 6 групп, период 20.11.2026 09:47 — 27.11.2026 00:00
     по Бишкеку (включая весь день 26 ноября), плюс технологические карты. Заменяет все занятия, отметки и оценки! Чтобы загрузить заново, смените значение.
   - `DEMO_ACTIVITY_VERSION=<любая строка>` — один раз для этой версии добавляет разнообразные отметки посещаемости, оценки за занятия
     и контрольные баллы за ПРОШЕДШИЕ занятия (`prisma/seed-demo-activity.ts`). Уже поставленные отметки и оценки не трогает.
     Чтобы дозаполнить занятия, которые прошли позже, смените значение.
7. Тестовые данные вручную (если нужно): `DATABASE_URL="<строка>" TEST_PASSWORD=... npx prisma db seed` (стирает данные!).

## Роли и экраны

- **Преподаватель:** журнал занятия, технологические карты, контрольные точки, итоги группы.
- **Руководитель направления** (`/program-head`): посещаемость, средний итог и карты преподавателей его направлений, отчёты групп только для чтения.
- **Учебная часть** (`/acadepartment/points`): лимиты баллов семестра и кнопка «Закрыть модуль».
- **Куратор:** освобождения (А) и подтверждение справок (Б), отчёты по посещаемости.

## Как считаются баллы

- Лимиты задаёт учебная часть (таблица `semesters`): 100 баллов за семестр, 50 за модуль, до 20 дополнительных.
- Преподаватель сам делит 50 баллов каждого модуля в **технологической карте** (`/teacher/tech-card`):
  посещаемость (необязательно), самостоятельная работа, рубежный контроль, текущий контроль.
  Текущий контроль дополнительно делится по занятиям: за занятие больше заданного поставить нельзя.
- **Посещаемость.** Баллы за занятие = баллы за посещаемость ÷ число занятий модуля.
  П, А и подтверждённая Б дают полные баллы, О — процент из карты (по умолчанию 50), НБ и неподтверждённая Б — ноль.
  Баллы за посещаемость не хранятся, а считаются из статуса при построении отчёта.
- Статус А и подтверждённую Б ставит только куратор. Преподаватель их не меняет.
- После закрытия модуля учебной частью оценки и карта этого модуля больше не меняются.
- Посещаемость можно исправить в течение 10 минут после конца занятия
  (`ATTENDANCE_GRACE_MINUTES` в `src/lib/class-session/attendance-window.ts`).
  Оценки остаются открытыми, каждое изменение пишется в `audit_trail`.
- Занятия группы по дисциплине нумеруются по дате: n-е занятие берёт n-ю строку карты
  (сначала модуль 1, затем модуль 2).

## Структура базы

`tech_cards` → `tech_card_modules` → `tech_card_lessons`; оценки: `lesson_scores` (за занятие),
`control_scores` (самостоятельная, рубежный, дополнительные). Остальное: расписание, студенты,
посещаемость, роли, аудит, интеграция с GAUDI.
